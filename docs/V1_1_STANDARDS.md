# V1.1 · 定位、产品建议与验收标准

## 定位与顺序

根据本轮明确需求，以“不同 AI Agent 的数据写入和读取中间平台”为优先：Agent 生产和使用数据；Hub 保存权威记录、权限、版本与追溯；网页用于授权、查看、审核和纠错。保留原设计的 sources → versioned content → immutable artifacts → publications，不把飞书、浏览器缓存或渲染 HTML 变成权威数据库。

将先前的 UI/交互建议与 API 建议按可验证的优先级归并，而不是一次性把全部路线图冒充成成品。

## 本版完成与可复验标准

| 范畴         | 已落地                                                                | 验收标准                                                       |
| ------------ | --------------------------------------------------------------------- | -------------------------------------------------------------- |
| 同一业务服务 | /api/v1 与有权限的 MCP 工具共用 Schema、校验与存储逻辑                | REST 保存后 MCP 可读取；MCP 写入后 REST 原键重放返回同一资源   |
| 机器契约     | OpenAPI 3.1.1、MCP input/output schemas、接入指南、llms 索引          | 文档与接口来自同一操作表；示例通过运行时校验                   |
| 幂等         | PostgreSQL 回执；稳定 Agent 身份跨 Token 轮换                         | 并发同键只写一次；重启/恢复后不重复；异体同键 409              |
| 并发写入     | expected_version + 稳定 block_id 的局部操作                           | 同基准版本只有一个成功，另一个取得可恢复冲突                   |
| 权限         | 独立 Agent、项目白名单、9 项操作权限                                  | 搜索、读、引用、文件、变更、重放均检查权限；不能绕到旧接口     |
| 低上下文读取 | 默认摘要、Unicode 文本分页、单个完整区块、游标版本固定                | 不同时返回全文与区块；正文更新不使分页混入新版本               |
| 外部文件     | 实际字节上传、小文本保存、原文件与预览分开、产物登记                  | 下载字节 SHA-256 与原文件一致；历史产物不被覆盖                |
| 变更与审计   | 项目提交顺序游标、历史修改事件、最近调用台账                          | 全链路事务一致；权限过滤事件；不记录请求正文和明文凭证         |
| 管理台       | 创建项目、授权、轮换、撤销、能力/文档入口                             | 不把“有授权”标为“在线”；密钥关闭后不出现在列表                 |
| 人工纠错安全 | 修复保存响应覆盖新输入和首次保存重挂载；删除区块可撤销；错误持续可见  | 慢网保存中继续输入，响应返回后输入仍保留，二次保存/刷新一致    |
| 阅读与触控   | 放大摘要/标签/元信息，提高对比，移动端高频按钮 44px，减少动态效果可选 | 390px 无横向溢出；关键动作可触控。不是全站 WCAG 认证声明       |
| 升级与备份   | 新增 002 迁移；原数据进入 default 项目；格式 2 备份兼容格式 1         | 不修改已应用 001；新文件、项目、变更和回执完整恢复；凭证不恢复 |

验收使用真实 PostgreSQL/PGlite、实际 Next.js 生产服务、Chromium 和官方 MCP SDK；不把 UI 截图、某个 Agent 的“已完成”答复或测试脚本存在当作测试通过。

## 刻意不在本版完成的部分

第一组是需要进一步设计/实现的能力：OAuth 项目范围写授权、自动暂存与正式版本分离、完整连续富文本编辑器、完整撤销历史、字符锚点式事实引用、视觉化版本差异、浏览器历史与筛选记忆、持久任务执行器、URL 抓取新工具、webhook/SSE、大文件直传。

第二组是需要真实外部环境接入的能力：用户 VPS/HTTPS 域名、对象存储账号、真实各家 Agent 账号、凭证服务器和媒体发布。未连接不写成“已连通”，未发布不显示“发布成功”。旧版 OAuth 保持只读，不能静默扩大授权。

人工编辑器仍使用兼容保存接口；本版验证了输入覆盖修复和失败保留，不宣称提供离线持久草稿、所有网络故障下的 UI 幂等保存或完整协同富文本。新 Agent API 的幂等契约是独立的已验收能力。

## 后续排序

P0 核心可靠读写已作为本版交付主体。P1 下一步重点应是获准 OAuth 写接入与持久任务/外部适配器，按真实客户端做端到端联调。P2 再继续首页任务化、内容详情工作台、引用差异、导出预览和更完善的编辑器，不以装饰性动效替代可靠性。
