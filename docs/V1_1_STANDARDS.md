# V1.1 改进标准与范围

## 定位修正

本文件汇总用户明确的“多 AI Agent 数据写入和读取中间平台”定位，以及前序交互/UI、API 建议。原设计中保留的核心是：Hub 为权威数据源；sources → content@version → immutable artifacts → publications；平台凭证不返回模型。人类网页主要用于授权、核查、纠错，不以替代专业长文编辑器为第一目标。

实现阶段仍采用 Next.js、PostgreSQL/PGlite 和私有内容寻址文件存储，不重建整套后端，不引入额外队列平台。

## 已落实的验收标准

| 标准                 | 实现与验证方向                                                                  |
| -------------------- | ------------------------------------------------------------------------------- |
| API 可发现、可验证   | capabilities、共享 Zod 输入输出契约、OpenAPI、MCP 工具定义、网页指南与 llms.txt |
| REST 与 MCP 一致     | 同一个 execute 服务，不维护两套核心写入                                         |
| 少占上下文           | 摘要优先、Markdown/blocks 分离、范围与截断标记、版本固定                        |
| 可靠写入             | 必需幂等键、稳定身份作用域、事务性回执、同键不同参数冲突                        |
| 并行修改安全         | expected_version、稳定 block_id、原子操作批次、历史版本不变                     |
| 失败可以修复         | 稳定 code、字段错误位置、request_id、retryable、版本冲突恢复动作                |
| 外部文件是一等资源   | 实际字节上传、服务器摘要、格式检查、文件与正文版本绑定、附件下载                |
| 最小权限             | 独立 Agent、项目范围、操作 scope、旧入口防绕过、可停用和撤销                    |
| OAuth 不偷偷扩大权限 | 预注册客户端绑定 Agent、显式同意、PKCE、保留/缩小刷新 scope                     |
| 数据来源可追溯       | 认证 principal 与自报 recipe 分离、默认未核实资料、增量变化记录                 |
| 控制台准确表达状态   | 显示“已授权/已停用”，不虚构在线；查看最近请求结果                               |
| 人工修正不丢输入     | 保存期间保留新编辑，首次保存不重挂载编辑器；区块删除可撤销                      |
| 可读与可触控         | 提升摘要、标签、辅助文字对比与字号，移动关键操作 44px 目标                      |
| 旧数据与恢复         | additive 002 迁移、V2 项目/文件备份、恢复身份默认停用、兼容 V1 数据             |

## 验收方式

单元/集成测试验证数据真实结果；同套集成测试在 PGlite 与独立 PostgreSQL 17 上运行。浏览器验收使用实际 Next.js 生产服务：网页登录建立身份，独立 HTTP 客户端写入，官方 MCP SDK 读取/写入，同键重放，再由 HTTP 读取及校验文件字节。

UI 单独注入延迟的首次保存响应，验证请求后继续输入不会被覆盖，验证删除区块撤销及刷新持久化；检查 390px 视口，并保留桌面、移动截图。

测试通过不等于第三方安全认证，也不等于用户真实平台账号已经接通。验收日志与 PR/CI 结果记录实际执行结果，不由本文件预先宣称通过。

## 明确推迟，未冒充已完成

- 后台 jobs、可靠执行器、source_capture 异步抓取、Webhook 与自动唤醒 Agent。
- 大文件分片/签名直传、原始视频转码、自动生成预览、恶意软件扫描。
- 全功能所见即所得编辑器、完整自动暂存、离线恢复、跨设备协同编辑。
- 全站按文章聚合的资料/分发工作台、首页全面任务化、浏览器历史/筛选位置全量重构。
- 字符区间级引用锚点、事实自动核验、跨版本可视化 diff。
- 第三方自动发文、用户凭证服务器接入、飞书同步与实际云存储账号联调。
- 通用 Agent 编排器、任意 SQL/文件路径执行、全库万能工具。

这些推迟项不应出现在“可用能力”列表里。capabilities.supported 明确列出关键边界。授权改变、备份恢复后客户端要重新同步，不能依赖旧游标得到新增可见历史。

## 1.1.1 补充验收

对不确定写入结果、重试快照、传输错误边界和人工纠错继续加固，详见 [`V1_1_1_RELIABILITY.md`](V1_1_1_RELIABILITY.md)。保留 1.1 已合入的数据模型和 001/002 迁移，不用不同的并行实现覆盖已执行迁移。最终以主分支的数据库、官方 MCP SDK、HTTP 和真实浏览器 CI 结果共同验收。

## 1.1.2 配置可用性补充

维护根目录 `.env.local`，统一原生启动/构建/迁移/恢复的 Next.js 环境解析行为。新增脱敏 `doctor` 与 JSON 检查结果、安全首次初始化和 Compose 初始化助手；启动前校验但构建不要求实时服务。自检不联网、不迁移、不改写业务数据。具体配置行为和边界见 `ENVIRONMENT.md`，不改变既有 Agent 契约与迁移文件。
